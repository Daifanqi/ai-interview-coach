## 7. 错误分析

（主体待填：`ml/error_analysis.py` 生成的题型/档位/长度误判模式，以及单一标注者的适用性警示——工具本身已经把这条警示写死进每次生成的报告里，不需要在这里重复措辞，直接引用即可。）

**方法论要求（现在就定下来，不等真实数字）**：如果第5节"数据增强前后对比"里，增强前vs增强后的验证集指标出现明显变化——不论是变好还是变坏——在这里补一次**长度伪影交叉检查**，不能只看指标数字就下结论。

背景：`ml/augment.py` 的回译增强会让*训练*样本系统性变长（fold 0 实测平均长23%，中位数长20%，见 `ml/augment_review.md`），这是翻译副作用，不是结构变化本身。如果模型从增强训练数据里学到"更长=结构更完整"这种捷径而不是真实的结构信号，会在（未被增强、长度分布不变的）验证集上表现为：增强后模型在原本就较长的真实答案上误差改善更多，在较短答案上改善有限甚至变差——这种情况下，第5节指标的变化不能直接当作"微调更强了"写进结论，必须在这里如实注明这个保留意见。

检查方法已经实现好了，不需要临时写代码：

```bash
python ml/error_analysis.py --model xlm-roberta-base --compare-augmentation
```

（对应 `ml/colab_run.ipynb` 第8b步；本地已用假数据自测过 `compare_length_bias()`/`length_error_correlation()` 的检测逻辑，见 `ml/self_test.py` 第6节。）

输出（`ml/results/error_analysis/xlm-roberta-base_vs_xlm-roberta-base__augmented_length_bias.md`）给出三个信号，写报告时三个都要看，不能只挑一个：

1. 长度 vs 有符号误差的相关系数（增强前、增强后分别算一次）；
2. 长度 vs "增强后减增强前的误差变化量"的相关系数——**这是最直接的信号**，明显负相关（越长的答案误差改善越多）就是长度伪影的可疑信号；
3. 按长度分三档（短/中/长）看平均误差变化量——如果"长"这一档改善明显比"短"这一档更多，同时信号2也偏负，两个信号一致指向长度伪影。

如果三个信号都没有明显的长度依赖（相关系数接近0、三档误差变化差不多），才能把第5节的指标变化写成"结构判断能力的真实提升/下降"；如果检测到长度伪影迹象，报告结论里必须明确注明"这个变化可能部分或全部来自训练数据长度分布偏移，不能确认是结构信号本身的提升"，不能回避这个保留意见。

小样本提醒：CV pool只有128条，配对相关系数在这个量级下噪声本来就大，检查结果是排查线索、不是因果证明——如果信号模糊（比如相关系数在-0.3到0之间摇摆），如实写"不确定"比强行下结论更诚实。
